# TradeClimb v2 priorities

## Implemented foundation

- Integrated the completed V1 leaderboard, sidebar/theme improvements, and compact evaluation/tuning interface from main.
- Added the versioned `sharpe_daily_v1` objective for new campaigns, daily portfolio-return metrics, objective-aware tuning, leaderboard ranking, and scalar-only validation feedback. Existing CAGR campaigns/results and the global validation ledger are preserved. See [metric conventions and compatibility](api.md). Existing risk eligibility stays in force; the 15% growth setting remains an aspiration.

## Remaining priorities

1. **Complete agent/owner separation.** Strategy execution/build isolation, aggregate resource limits, network/filesystem confinement, and model mediation are implemented. Keep validation data inaccessible to development agents through separate accounts/environments; same-owner agents remain trusted.
2. Add authenticated roles and owner-only validation inspection, especially before exposing TC beyond a trusted LAN or moving it into a shared cluster.
3. Introduce a final untouched test and walk-forward evaluation, historical universes including delistings, and stronger multiple-testing diagnostics.
4. Add historical quotes/books, partial fills, latency, queue/limit orders, and calibrated liquidity assumptions. Revisit NautilusTrader or Barter behind the TC SDK then.
5. Add point-in-time model/feature datasets. Historical model knowledge remains accepted in v1 but should not be confused with historical predictive ability.
6. Build automated strategy invention and agent coordination in the separate orchestrator repository. TC provides evaluation, budgets, lineage, and paper promotion interfaces.
7. Add distributed worker packaging for Kubernetes only after measuring local bottlenecks.

Real exchange orders require another explicit execution and operations review. They are not available in v1.

## Local isolation implemented

This machine is the approved target. External historical/paper strategies now use mandatory Bubblewrap namespaces and systemd cgroups; isolated offline compilation includes Cargo build scripts, and per-run Unix sockets mediate model inference. The existing AppArmor profile works without global policy changes. See [setup, budgets, tests, and remaining owner/agent boundary](operations.md#strategy-isolation). Authentication and separate development-agent accounts are still pending; application execution confinement does not isolate an agent with owner filesystem access.

## Approved evaluation policy (4 November 2026)

The owner confirmed that August–October 2026 is untouched and reserved `[2026-08-01, 2026-11-01)` as the final test. Keep development `[2022-11-01, 2025-11-01)` and shorten validation to `[2025-11-01, 2026-08-01)`. New campaigns now reserve these dates, including when using the legacy CAGR objective. Ordinary submissions and workers reject overlaps; history, report, and leaderboard routes suppress any cached results covering the reservation. Post-holdout warmup excludes reserved candles. No final-test execution/reveal endpoint has been added: reservation is implemented, while owner-controlled one-time final evaluation and walk-forward analysis remain pending. Do not run the final test during development or data-source research.

The owner explicitly accepted the documented Bitvavo gaps for research and requested three ranked ways to obtain better data. Reimport into this V2 worktree with the explicit gap override, retain coverage warnings and immutable identity, and never substitute other-venue prices into Bitvavo candles. The [ranked data-source research](research.md#v2-data-source-shortlist--checked-4-november-2026) and [coverage metadata](v2-data-source-audit.json) record the alternatives. No alternative data purchase is authorized.

The accepted historical-model-knowledge policy and paper-only scope remain in force.
