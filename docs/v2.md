# TradeClimb v2 priorities

## Implemented foundation

- Integrated the completed V1 leaderboard, sidebar/theme improvements, and compact evaluation/tuning interface from main.
- Added the versioned `sharpe_daily_v1` objective for new campaigns, daily portfolio-return metrics, objective-aware tuning, leaderboard ranking, and scalar-only validation feedback. Existing CAGR campaigns/results and the global validation ledger are preserved. See [metric conventions and compatibility](api.md). Existing risk eligibility stays in force; the 15% growth setting remains an aspiration.

## Remaining priorities

1. **Integrate the future orchestrator.** Owner/agent roles, private storage, separate-account/network-isolated launcher, development-only API and revocable credentials are implemented. The strategy-orchestrator project has not started; wire reviewed tooling and candidate handoff there without granting owner credentials or general network access.
2. Extend the browser reporting for the implemented owner CLI evaluation controls.
3. Extend the implemented final-test and development walk-forward controls with historical universes including delistings and stronger multiple-testing diagnostics.
4. Add historical quotes/books, partial fills, latency, queue/limit orders, and calibrated liquidity assumptions. Revisit NautilusTrader or Barter behind the TC SDK then.
5. Add point-in-time model/feature datasets. Historical model knowledge remains accepted in v1 but should not be confused with historical predictive ability.
6. Build automated strategy invention and agent coordination in the separate orchestrator repository. TC provides evaluation, budgets, lineage, and paper promotion interfaces.
7. Add distributed worker packaging for Kubernetes only after measuring local bottlenecks.

Real exchange orders require another explicit execution and operations review. They are not available in v1.

## Local isolation implemented

This machine is the approved target. External historical/paper strategies now use mandatory Bubblewrap namespaces and systemd cgroups; isolated offline compilation includes Cargo build scripts, and per-run Unix sockets mediate model inference. The existing AppArmor profile works without global policy changes. See [setup, budgets, tests, and owner/agent boundary](operations.md#strategy-isolation). The private-tool security milestone now provides owner sessions, restricted/revocable agent credentials, private data/backup directories, a separate locked agent account and network-isolated launcher. Owner credentials cannot use the agent Unix endpoint. Programs run directly as the owner remain trusted and outside the agent boundary.
